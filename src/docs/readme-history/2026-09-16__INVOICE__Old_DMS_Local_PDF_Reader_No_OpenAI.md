# Old DMS Invoice Local PDF Reader — No OpenAI Key Required

Date: 2026-09-16
Module: Sales Invoice / Purchase Invoice / Bulk Scan & Fill

## Why
Bulk Invoice Scan previously called OpenAI before attempting any local extraction. Therefore an old DMS PDF failed with `OPENAI_API_KEY is not configured on the backend`, even though the PDF already contained selectable text.

## New extraction order
1. For Sales/Purchase PDF uploads, extract PDF text locally with `pdf-parse`.
2. Detect Old DMS / common Tax Invoice labels.
3. Extract invoice number, date, party/supplier GSTIN and name, product rows, HSN, quantity, unit, basic rate, GST rate, taxable/basic value, GST totals, round-off and invoice value.
4. Match GSTIN/name to Customer/Supplier Master.
5. Match product name/SKU/HSN to Product Master.
6. Show the existing Bulk Scan review UI.
7. Final Post uses the existing Sales/Purchase transaction engine, so normal stock/GST/ledger/accounting rules remain unchanged.
8. OpenAI is optional fallback only for files that are not locally readable text PDFs.

## Dependency
Backend package.json now includes:
- `pdf-parse` ^2.4.5

After applying this patch run `npm install` in the backend folder once.

## Notes
- Original text PDFs generated by Old DMS do not need `OPENAI_API_KEY`.
- Image-only/scanned invoices still need an OCR/AI path; if no OpenAI key is configured, the UI returns a clear message rather than the old generic key error.
- Scanned totals are shown in review as a cross-check. Final invoice totals are still calculated by V2 from the reviewed line items.
